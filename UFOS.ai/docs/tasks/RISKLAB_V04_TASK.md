# RISKLAB v0.4 — validation report pipeline (figures, tables, LaTeX skeleton, survivorship study)

Goal: the code side of the **model validation report** (career plan showcase piece 2). The user writes the prose
outside this chat; this round builds everything that comes from code and leaves clearly marked text slots. Builds on
v0.3 (commit 9d44267). All earlier rules stay in force: synthetic data only, deterministic, no silent fallbacks,
English, `check_repo_data.py`, no git.

## 1. Dependencies
- Add `matplotlib` as an optional extra `report` in `pyproject.toml` (`pip install -e .[report]`) and in
  `requirements.in` (a separate `requirements-report.in`). The core package and the core tests must still run
  without it: report tests skip with a clear message when it is missing.
- Use the Agg backend, a fixed style defined in code (no user rcParams), DejaVu fonts (bundled with matplotlib),
  and fixed figure sizes. For PNGs, strip or fix the metadata (`metadata={"Software": None}`) so the same inputs give
  byte-identical files where matplotlib allows. For the PDF figures, fix `CreationDate`. Test and document the
  reproducibility that is actually achieved.

## 2. New small study: estimation window (`studies/estimation_window.py`)
- On garch_t6 data, T=1000, 99 % VaR: GARCH-t and FHS with estimation windows {250, 500, 750, 1000}.
- Report per window: the exceedance rate ± se, Kupiec / binomial / cc / Z2 rejection rates with reference sizes,
  and the mean relative VaR error vs the truth.
- Smoke / default / full modes; measure the runtimes. Save the full-run summary in `studies/results/`.
- This turns the v0.3 finding ("over-rejection is estimation risk") into a curve.

## 3. Survivorship-bias study (`studies/survivorship.py`)
- A synthetic universe of N firms with a 10-year revenue-growth process: idiosyncratic growth draws, and a
  hazard of failure / acquisition that rises with poor growth (documented parameters).
- Compute "base rates" (share of firms reaching ≥ g % CAGR over 10 years) twice:
  (a) survivors only, as a naive database of currently listed firms would; (b) the full cohort including dead
  firms.
- Report the bias (a − b) per growth threshold with Monte-Carlo se. A sensitivity sweep over the hazard strength
  shows when the bias matters.
- Purpose: a self-contained, data-licence-free demonstration for the report's data-quality section. Name no real
  firms and no real data.

## 4. Figures (`src/risklab/report/figures.py`, generated by `report/build_figures.py`)
Each figure is built from the saved study results (`studies/results/*.json`) or from a fixed-seed simulation, never
from real data. Each has a function, a fixed file name and a caption string that the LaTeX build uses.
1. **Exceedance plot:** one GARCH-t6 path (T=1000). Losses, 99 % VaR of static normal vs GARCH-t (1000-day
   window), exceedances marked.
2. **Rejection rates by model and test:** grouped bars with ± 1.96 se error bars and a reference-size line per
   test (from the v0.3 full run).
3. **Estimation-window curve:** exceedance rate and rejection rates against the window length (from §2).
4. **Traffic-light zone shares** per model (stacked bars).
5. **10-day horizon:** bias and RMSE per method and data set, with error bars (from horizon_10d).
6. **Diagnostics:** a QQ plot of the GARCH-t standardised residuals against the fitted t, for one path.
7. **Survivorship bias:** naive vs true base rate against the growth threshold, plus the bias band (from §3).
- Colour-blind-safe palette; no titles inside the figures (captions carry the text); axis labels with units.

## 5. Tables (`src/risklab/report/tables.py`)
LaTeX tables (booktabs-free if booktabs is not available; check the TeX installation where the build runs) generated
from the results JSON:
- T1: the model inventory (model, assumptions, parameters, estimation window, refit cadence);
- T2: size table (reference sizes);
- T3: power table (models × tests at T=250 / 1000);
- T4: the estimation-window table;
- T5: the 10-day horizon table;
- T6: survivorship;
- T7: a **findings register** template (ID, finding, severity High / Medium / Low, evidence reference, proposed
  remediation). Pre-filled with the findings the studies support (e.g. "250-day window over-rejects the correct
  GARCH-t", "√10 scaling biased on GARCH data", "Kupiec size 9.5 % at T=250"), each linked to its figure / table.
  Severity proposals are marked `PROPOSED` for the user to confirm.
All numbers carry their ± se where they come from Monte Carlo.

## 6. LaTeX report skeleton (`RiskLab/report/validation_report.tex`)
Bank model-validation structure:
1. Executive summary;
2. Scope and model description;
3. Data (synthetic design, survivorship / data quality);
4. Conceptual soundness;
5. Implementation verification (tests, reproducibility, independent reviews);
6. Outcome analysis / backtesting;
7. Benchmarking and sensitivity (estimation window, horizon);
8. Limitations;
9. Findings and recommendations (T7);
10. Appendix (formulas, test definitions, reproduction commands).
- Every prose slot is a visible box `\usertext{<what goes here, 1–2 lines of guidance>}`, rendered as a coloured
  placeholder, so that a build with open slots is obviously a draft.
- Figures / tables are included via `\input` from generated files.
- A build script `report/build_report.py`: run the figures + tables, then pdflatex twice. Output to `out/report/`.
  The script stops with a clear message if pdflatex or a needed package is missing; no fallback renderer.
- Use only packages available in a minimal TeX installation, or vendor nothing and check at build time. Document the
  required packages.
- Build the PDF once in the cloud container. Commit the generated figures (PNG + PDF), the generated tables and
  `report/validation_report_draft.pdf` (synthetic only), so the README can link them. Size budget: total < 5 MB.

## 7. Tests
- Each figure function runs on tiny inputs and writes a file (skip without matplotlib); reproducibility check where
  achievable.
- Tables: a golden test on a small fixed results JSON (independent expected values).
- The survivorship study: the analytic check that the bias is 0 with zero hazard; it grows with the hazard
  strength; reproducible.
- The estimation-window study: smoke mode.
- build_report: a test that a missing pdflatex gives the clear error (mock), not a crash.
